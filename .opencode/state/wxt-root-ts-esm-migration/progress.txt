# Progress Log

PRD: wxt-root-ts-esm-migration
Started: 2026-04-19

## Codebase Patterns

- Repo is logically single-package, but tooling is split between root and `src/package.json`.
- Current extension runtime depends heavily on ordered global scripts and `globalThis.snipSnip*` exports.
- `service-worker.js` is a monolith and currently centralizes messaging, commands, downloads, notifications, and injection orchestration.
- `contentScript/pageContext.js` must remain an explicitly injected page-context bridge and stay web-accessible.
- Offscreen behavior must remain browser-aware: Chromium offscreen path plus Firefox fallback.
- Vendored libs should be wrapped first, not replaced during initial migration.
- Bun `catalog:` dependency refs were workspace-era plumbing; a true single-package root must inline concrete versions.
- Root linting must explicitly ignore vendored/minified browser assets; otherwise first-party lint gets swamped by third-party code.
- Root typecheck is temporarily TS-file scoped via `tsconfig.typecheck.json` until the JS-to-TS migration tasks land.
- Initial WXT scaffold can stay honest with `srcDir: 'src'` plus a minimal `src/entrypoints/background.ts`; this lets WXT build successfully before manifest parity work starts.
- For early WXT phases, explicit imports like `import { defineBackground } from 'wxt/utils/define-background'` avoid depending on generated auto-import magic.
- WXT Firefox builds must be forced to MV3 explicitly with `--mv3`; default Firefox builds otherwise drift to MV2.
- When a legacy web-accessible resource path must stay stable, putting the file in `public/` is simpler than forcing WXT entrypoint naming to match it.
- During TS migration, keep domain models in one importable TS module and let `src/global.d.ts` bridge legacy global runtime APIs back to those types.
- For classic-script migration phases, keep `.ts` as the canonical shared-module source and generate committed `.js` facades that preserve `globalThis.snipSnip*` and `module.exports` until runtime entrypoints are migrated.
- For stateful shared helpers, prefer direct TS imports plus small optional dependency-arg bags on the few functions that need runtime overrides; it is leaner than module factories and keeps tests decoupled from legacy globals.
- For vendored classic-script libs, add tiny `module.exports` footers where needed, then load them through typed TS wrappers that prefer existing globals and fall back to imported defaults.
- `tsconfig.typecheck.json` can stay TS-entrypoint-focused while still allowing vendored JS wrapper imports by setting `allowJs: true` with `checkJs: false`.
- For huge legacy entrypoints, avoid a risky whole-file rewrite: add a small WXT bootstrap that installs globals via imports, then patch the legacy file to read those APIs from `globalThis` instead of script-order locals.
- Background listener registration can stay synchronous in WXT if the entrypoint uses static imports for bootstrap + side-effect runtime loading instead of async wrapper calls in `defineBackground()`.
- When a legacy content script is imported as a module, any functions later probed by injected extension code must be reattached to `window`/`globalThis`; top-level module declarations no longer become globals automatically.
- If a page-context bridge must stay at an exact WAR path for manual injection, keep the emitted asset in `public/` and add a sync test so the legacy source copy cannot drift.
- WXT page entrypoints only work as a top-level file or one-level-deep `index.html`; if a legacy runtime path must stay different, adapt the caller with a small path helper instead of forcing a deeper entrypoint tree.
- For migrated legacy HTML shells, preload vendored globals through the existing wrapper layer before importing the legacy runtime module; this keeps Bun tests and WXT builds aligned.
- For legacy popup-style pages with huge static HTML and classic scripts, keep the old HTML as a raw template, inject its body into a tiny WXT entrypoint, and load legacy scripts/assets through a runtime URL map instead of duplicating the whole page.
- For legacy options/guide-style pages, keep the source HTML unchanged for old-path compatibility, then have the WXT bootstrap inject the raw shell, install globals/styles, and patch only the path-sensitive links at runtime.
