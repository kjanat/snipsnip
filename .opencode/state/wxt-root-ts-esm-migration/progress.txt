# Progress Log

PRD: wxt-root-ts-esm-migration
Started: 2026-04-19

## Codebase Patterns

- Repo is logically single-package, but tooling is split between root and `src/package.json`.
- Current extension runtime depends heavily on ordered global scripts and `globalThis.snipSnip*` exports.
- `service-worker.js` is a monolith and currently centralizes messaging, commands, downloads, notifications, and injection orchestration.
- `contentScript/pageContext.js` must remain an explicitly injected page-context bridge and stay web-accessible.
- Offscreen behavior must remain browser-aware: Chromium offscreen path plus Firefox fallback.
- Vendored libs should be wrapped first, not replaced during initial migration.
- Bun `catalog:` dependency refs were workspace-era plumbing; a true single-package root must inline concrete versions.
- Root linting must explicitly ignore vendored/minified browser assets; otherwise first-party lint gets swamped by third-party code.
- Root typecheck is temporarily TS-file scoped via `tsconfig.typecheck.json` until the JS-to-TS migration tasks land.
- Initial WXT scaffold can stay honest with `srcDir: 'src'` plus a minimal `src/entrypoints/background.ts`; this lets WXT build successfully before manifest parity work starts.
- For early WXT phases, explicit imports like `import { defineBackground } from 'wxt/utils/define-background'` avoid depending on generated auto-import magic.
